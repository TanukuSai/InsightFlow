# 1. THE NEW ART DIRECTION: “SIGNAL OBSERVATORY”

InsightFlow turns noisy, repeated customer statements into patterns and then into decisions. The visual system should express **signal emerging from noise**. The living dots are the brand's signature, not an incidental animated background.

The product should feel like a highly art-directed intelligence product: confident, editorial, analytical, slightly futuristic, and warm enough for business users. It must not resemble a generic SaaS admin template or a dashboard generated by dropping every feature into a grid of white rounded cards.

Keep the overall interface readable and suitable for long sessions, but create stronger contrast and drama using a purposeful combination of:
- warm, quiet canvas surfaces;
- deep ink / midnight surfaces for key focal areas;
- a distinctive high-chroma cobalt as the primary interaction accent;
- cyan/aqua as a secondary analytical signal;
- coral as an attention signal, not an all-purpose decoration;
- amber for caution and review;
- restrained violet only where a separate analytical series needs a distinct encoding.

Do not continue the previous monotonous pale-sage/forest-green wash. Forest green may remain a minor semantic or legacy accent, but it must no longer dominate the experience. Do not simply swap green for purple. Build hierarchy through composition, contrast, scale, typography, spacing, and data encoding—not merely bright colours.

### Foundation
- Warm paper: `#F5F5F1`
- Pure white: `#FFFFFF`

- Secondary ink: `#394457`

### Deep focal surfaces

- Raised midnight: `#19243B`
- Midnight border: `rgba(255,255,255,0.12)`
- Primary light text on dark: `#F7F9FC`
- Secondary light text: `#B8C2D5`

### Brand/action colours
- Signal cobalt: `#4F63FF`
- Cobalt hover: `#3C4FE6`
- Signal cyan: `#22C8D8`
- Coral: `#FF6B61`
- Amber: `#F4B740`
- Orchid: `#9B82F6`
- Positive teal: `#159A83`

Use these consistently through CSS variables/design tokens. Tune only where contrast or visual testing demonstrates a problem. Avoid creating near-duplicate shades ad hoc across components.

### Do not conflate semantic dimensions
Source category colour and sentiment colour must be separate visual systems. Never use category colour to imply sentiment.
- Sentiment positive: positive teal.
- Sentiment neutral: neutral slate.
- Sentiment negative: coral.
- Unknown/not analyzed: slate with explicit text.
- Warning / needs review: amber.
- Critical state: coral plus label/icon; never colour alone.

Source categories may use a restrained, fixed category palette (cobalt, cyan, amber, orchid) with a legend. The same category must retain the same colour across charts, badges, and filters. Keep these colours visually distinct from sentiment states where possible.

## 1.2 Typography

Use the project's installed Inter/Geist setup if available. Create a real hierarchy:
- Dashboard headline: 30–36 px desktop, line-height about 1.1.
- Supporting statement: 14–16 px with readable line-height.
- Primary KPI values: 32–44 px, tabular numerals where possible.
- Section titles: 17–20 px.
- Table body: 13–14 px minimum where dense layout requires it.
- Labels and metadata: normally 12–13 px; do not make important content microscopic.

Use weight and scale rather than putting every heading in a pill or adding an icon to every label. Numeric values should align visually. Avoid excessive uppercase micro-labels and letter-spaced metadata.

# 2. GLASSMORPHISM — FOCUSED AND VISIBLE, NOT EVERYWHERE

The current glass treatment is too subtle to create a coherent visual identity. Implement visibly layered glass where it adds depth, and stop using the same flat white card style for everything.

Create reusable surface variants:

1. `glass-nav`: translucent light glass for floating navigation/header controls, with about 18–24 px blur, a delicate high-light border, and soft depth.
2. `glass-dark`: translucent white over a midnight surface for selected focal panels, with a subtle inner highlight and not-too-bright border.
3. `glass-popover`: legible, elevated translucent surface for menus and filter popovers.
4. `solid-data`: opaque surface for charts, data tables, long feedback content, and dense form controls.
5. `quiet-section`: no card border; a content region defined by spacing and typography.
6. `signal-panel`: a prominent dark panel for the dashboard's top insight / evidence narrative, with controlled particle/connecting-line artwork.

Guidelines:
- Use `backdrop-filter` and `-webkit-backdrop-filter` with fallbacks.
- The effect should be visible when looking at the screen, but never reduce text contrast.
- Do not place each dashboard component inside a floating glass rectangle.
- Use a dark/colour focal surface only for a few high-value areas; preserve a calm base canvas elsewhere.
- Shadows should create depth, not a dark outline around every component.
- Avoid generic blur blobs, neon glow everywhere, or large gradient washes.
- Respect reduced motion and browser performance.

# 3. REDESIGN THE DASHBOARD COMPOSITION FROM FIRST PRINCIPLES

Do not keep the current composition and merely recolour it. Rework the page hierarchy and spatial rhythm. The dashboard must have a clear visual story and obvious focal point at first glance.

## 3.1 Desktop target

Design for 1440 × 900 first; also validate 1280 × 800 and mobile 390 × 844.

Keep a strong, compact navigation rail/sidebar, but avoid letting it dominate the page. Use a dark midnight sidebar with a restrained active cobalt indicator and quiet unselected items, OR a carefully composed warm sidebar with dark focal controls; pick one approach and apply it consistently. Prefer the midnight sidebar if it gives the page the contrast it currently lacks.

The main content area should use a 12-column grid, balanced maximum width, larger gutters, and consistent vertical spacing. Avoid cramming every module above the fold. The page should have hierarchy and breathing room.

### Zone A — page heading and workspace context

- Title: “Feedback overview” or an equally clear user-facing name.
- A short line clarifying what the current workspace/dataset represents.
- Dataset source/analysis status in a compact, credible indicator.
- Primary actions: `Import CSV` and `Build report`.
- Avoid too many badges on one row. Don't repeat the workspace name in multiple places.

### Zone B — signature “Signal Brief” panel

This is the dashboard's visual anchor. Use one broad dark midnight panel, roughly 8–9 columns of the grid, paired with a narrower insight/quality panel if there is a genuinely useful reason.

The panel should combine:
- a short, evidence-based headline about the dataset;
- one or two key pieces of contextual information;
- the living-dot “signal emerging from noise” visual, constrained to the right side or background of the panel;
- an action such as `Inspect repeated statements` or `Review findings` that navigates to real records.

The dots must remain subtle enough for text readability and should not steal focus from the message. The particles should be meaningfully tied to a visual story, not randomly animated confetti.

Do not invent a business conclusion. Before analysis runs, the panel should say that the source dataset has been imported but has not yet been analyzed. After analysis, it may state only a conclusion actually present in backend results and cite the supporting records/counts.

### Zone C — KPI row

Use three or four KPI cards maximum. Give them enough space to feel intentional rather than like tiny tiles in a dense grid.

Choose metrics that are actually available, for example:
- total source rows;
- unique exact statements;
- additional repeated rows;
- analyzed feedback or analysis coverage.

Do not show a fabricated average sentiment, percentage change, customer count, critical-issue count, or model status. If a metric is unavailable, display `Not analyzed` or a useful empty state—not a fake zero.

KPI style:
- one larger numeric value;
- concise title;
- a one-line interpretation;
- a small icon only if it conveys meaning;
- optional detail action.

Not all four cards should have the same decoration. Use one highlighted brand card and quieter neutral cards. Flip-card backs may show a calculation explanation, but the front must remain understandable on its own.

### Zone D — central analytical area

Use an editorial asymmetrical composition, not a uniform matrix of cards.

Recommended structure:
- Left / 5 columns: `Source category distribution` with ranked horizontal bars.
- Right / 7 columns: `Most repeated statements` as a ranking/Pareto-inspired visualization and evidence list.

The visualization must answer a question clearly. Use labels, precise counts, percentages, and supporting text. Do not add a chart merely to fill space.

A repeat-count chart is particularly relevant because the dataset contains many repeated exact text statements. Make that pattern a signature analytical feature of InsightFlow.

### Zone E — issues requiring inspection

Display a clean, ranked issue/evidence area with only the most important few items initially visible. Each item should present:
- issue or repeated-statement title;
- source category, if supplied;
- exact number of source rows;
- unique exact statement count where relevant;
- a clear `Inspect evidence` action;
- a priority label only if the backend has a defensible priority/rationale.

Avoid fake “critical” statuses merely because a statement repeats many times. Repetition warrants inspection; it does not itself prove severity or distinct affected customers.

### Zone F — recent/source feedback

Present a readable, compact source-record table/list below the major insights. Show original excerpts and stable row IDs. Since the CSV has no timestamps, label the order as source/import order—not recency. Do not invent source systems or relative times like “24m ago”.

### Zones to remove or demote

- Do not show a fabricated trend chart.
- Do not show several similar warning strips.
- Do not render large explanatory policy paragraphs in every chart card; use a concise note with a `Why?` expansion or accessible tooltip.
- Do not repeat the same duplicate-data caveat in every section.
- Do not put every section inside the same white border/radius/shadow.
- Do not display sample data as though it came from the real dataset.

# 4. DATA VISUALIZATION STANDARDS

Use the existing chart library if it is suitable. If Recharts or another library is installed, prefer improving its use over adding a second chart framework.

Every visualization must answer a clear analytical question and have accessible labels, a legend when needed, helpful tooltips, and a text-based interpretation. Use animation sparingly; chart values must not be hard to read because of movement.

## 4.1 Source category distribution

Use ranked horizontal bars sorted descending.
- Category label left.
- Bar in stable category colour.
- Right-aligned exact count.
- Percentage share in a secondary typographic style.
- A clear total `N` and a label such as `Source category — not sentiment`.
- Axis/grid only if it meaningfully improves comparison.
- Do not use a pie/donut as the main way to compare four close values; a ranked bar is easier to compare.

## 4.2 Sentiment

Only display actual sentiment results after analysis has produced them.
- Use three sentiment categories with explicit labels and counts.
- A compact segmented bar can show composition; pair it with values and a clearly described denominator.
- Unknown/not analyzed records must be shown separately or excluded with the exclusion explained.
- Do not derive sentiment from source category.
- Do not display a 1–5 average unless a real, valid numeric sentiment score exists.

## 4.3 Repeated statement ranking / Pareto

This is a product differentiator.
- Show the top repeated exact statements with readable truncation and click-to-inspect full verbatim text.
- Show exact row counts and unique statement status.
- A Pareto cumulative line is optional only if mathematically calculated from the displayed records and is not visually confusing.
- Never imply unique customers when no customer identifier exists.
- Ensure that a long statement can be inspected in a drawer without losing chart context.

## 4.4 Issues and evidence

Do not use a chart for everything. A ranked dossier/list can communicate issues more effectively than a chart when the labels and evidence matter.
- Use an explicit priority rationale.
- Distinguish source row frequency from semantic cluster size and distinct statement count.
- Make evidence accessible with one action.
- Avoid asserting “root cause”, “systemic risk”, “outbreak”, or “business loss” unless supported by actual analysis/evidence.

## 4.5 Temporal visualization

The supplied CSV schema currently contains `review` and `category`, not a verified timestamp.
- Do not generate historical trend lines, week-over-week comparisons, date-based “recent” claims, or animated time-series simulations as if factual.
- Remove the large fake/illustrative line chart from the production dashboard.
- Replace it with the repeated-statement analysis, analysis coverage, or a clear temporal-data-unavailable block.
- If a demo simulation toggle exists, it must be visibly marked illustrative and off by default. Prefer not to show simulated time data on the actual dataset dashboard.

## 4.6 Chart microinteraction quality

- Tooltips should be visually refined, compact, and high contrast.
- Hover should highlight the selected series/bar and de-emphasize others subtly.
- Use data-label transitions only when they don't cause layout shifts.
- Avoid animated bars growing from zero on every render/refilter.
- Do not rely on colour alone; show labels and counts.
- Honour reduced motion.

# 5. THE LIVING DOTS — SIGNATURE BRAND ELEMENT

Inspect and reuse the existing `DataFieldCanvas.tsx`; don't throw it away without testing it.

Make the dots materially more distinctive and intentional:
- Use particle density that fits the container and device.
- Give particles a purposeful flow and cluster formation.
- Use fine, low-opacity connecting filaments only when proximity/relationship is meaningful.
- Use the core palette: restrained cobalt/cyan, occasional coral/amber, and mostly subtle neutral points.
- No rainbow particles; no all-particles-bright treatment.
- Create four controlled narrative states where used in a story: scattered feedback → repeated statements cluster → category groups become visible → evidence is linked to actions.
- Use the states to make a point in the landing story, not run as a meaningless perpetual slideshow.
- In the dashboard, use a calmer looping/ambient version or a stable visual state; never let particles cause visual noise behind a chart or paragraph.
- Support pause/stop when offscreen or tab-hidden and `prefers-reduced-motion`.
- Cap device pixel ratio and avoid expensive per-frame React state updates.
- Avoid a canvas that intercepts clicks (`pointer-events: none` unless interaction is explicitly intended).

The landing page can use the most expressive version. Authenticated dashboard use should be more restrained.

# 6. MOTION DESIGN — FEWER, MORE PURPOSEFUL ANIMATIONS

Do not call the project animated merely because an element changes opacity. Create an intentional motion language.

Use these as starting ranges:
- Hover/press response: 120–180 ms.
- Small popover/menu: 160–220 ms.
- Drawer/dialog: 220–280 ms.
- KPI flip: 380–460 ms with a confident ease curve.
- Dashboard layout transition: 250–350 ms.
- Landing story stage transition: 500–800 ms only when triggered by meaningful scroll/interaction, not every few seconds without cause.

Motion rules:
- Entrance should communicate hierarchy: hero/message first, data second, supporting controls third.
- Avoid animating every card when the page loads.
- Use small surface-lift and border/lighting shifts on hover, not large bouncy scaling.
- Avoid springy motion for business-critical data.
- Avoid blur animations on every element; they can feel sluggish and impair text rendering.
- Prevent layout shifts.
- Don't animate charts from zero on every state update.
- Ensure flip cards work with mouse, keyboard, touch, and reduced-motion settings.
- Respect the existing `prefers-reduced-motion` implementation.
- Avoid continuous particle movement when the visual isn't in view.

Animations should feel tactile and premium, not like a demo reel.
